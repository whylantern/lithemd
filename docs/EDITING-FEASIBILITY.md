# LitheMD 编辑能力可行性分析

> 对应任务 A2。本文只做技术分析，不代表 2.4.0.0 立即实现编辑功能。
> 全局约束见 `docs/REQUIREMENTS.md`。

## 1. 目标分层

编辑能力按投入分为四级：

| 级别 | 能力 | 用户价值 | 实现难度 |
|---|---|---|---|
| E1 | 源码编辑 + 保存 | 能改文本并保存 | 中 |
| E2 | 源码编辑 + 实时预览 + 脏标记 + 冲突处理 | 接近普通 Markdown 编辑器 | 中高 |
| E3 | 预览区点击/选区修改，映射回 Markdown | 接近 Typora | 高 |
| E4 | 完整所见即所得（表格、列表、图片、公式均可视编辑） | 完整编辑器 | 很高 |

建议只先评估 E1/E2，暂不把 E3/E4 纳入近期版本。

## 2. E1：源码编辑与保存

### 可实现内容

- 新增可编辑文本视图，复用当前源码视图的排版和滚动；
- 支持插入/删除、选区、复制粘贴、撤销/重做；
- `Ctrl+S` 保存原文件；
- 未保存标记；
- 关闭标签、退出应用时提示保存/不保存/取消；
- 保留当前文档编码，保存时写回原编码；
- 保存失败、只读文件、文件被占用时明确提示。

### 主要难点

1. **文本编辑控件**：当前源码视图是自绘只读，需要实现光标、选区、输入法、双击选词、拖选、滚动跟随。
2. **撤销/重做**：需要字符级或操作级历史，不能只依赖整文件快照。
3. **编码回写**：当前读入后会解码为宽字符；保存必须按原编码重新编码，并处理无法表示的字符。
4. **换行与 BOM**：保留 CRLF/LF 和 BOM，避免每次保存产生全文件 diff。
5. **文件冲突**：外部修改、只读、被占用、网络盘延迟。
6. **大文件**：不能把每次按键都重新排版整个大文件，需要分块/虚拟化。

### 可行性

中。适合作为第一版编辑能力，但需要独立的 `TextEditor` 核心模型和 Win32 输入处理。

## 3. E2：实时预览与冲突处理

### 可实现内容

- 编辑缓冲区与预览区并排或上下切换；
- 输入后延迟重排预览；
- 脏标记；
- 文件监听检测外部变化；
- 保存前检测磁盘版本，冲突时询问覆盖/重新加载；
- 自动保存可选（默认关闭）。

### 主要难点

- Markdown 重排性能：每次输入都重新解析全部块会很慢，需要增量解析或延迟合并；
- 预览滚动位置保持；
- 撤销历史与预览同步；
- 编辑期间注释/画笔层的位置稳定性。

### 可行性

中高。可在 E1 稳定后实现；需要 Core 层提供 `MarkdownDocument` 增量更新接口。

## 4. E3：预览区直接编辑

legacy 使用 `data-source-line` 和反向 Markdown 转换实现“预览编辑”。原生实现难度明显更高：

- 每个渲染块必须保存源码行范围；
- 编辑预览块后要反向生成 Markdown；
- 表格、列表、引用、代码块、公式、图片都要可逆；
- 富文本 DOM 到 Markdown 的转换容易丢格式；
- 与当前自绘布局、文字选择、注释层叠加复杂。

### 可行性

高投入、高风险。不建议在 2.4.x 早期实现。若做，应先只支持段落/标题/列表，再逐步扩展。

## 5. E4：完整 WYSIWYG

需要实现类似文字处理器的编辑模型：

- 段落/行内样式树；
- 表格行列编辑；
- 图片拖放/缩放；
- 公式编辑器；
- 代码块和语法高亮编辑；
- 输入法、组合键、无障碍；
- 自动保存、版本冲突、崩溃恢复；
- Markdown 序列化保真。

### 可行性

低（在保持轻量、单 exe、无 WebView 的前提下）。不建议把完整 WYSIWYG 作为近期目标；它会显著增加代码量和维护成本。

## 6. 与现有注释/笔记的关系

- 编辑正文不应破坏现有按文档路径哈希保存的笔记；
- 保存正文时不要覆盖 `lithemd-notes`；
- 如果文档重排，注释坐标是否跟随需要单独设计；
- 建议第一版编辑时限制在“保存/另存为”，不自动移动或删除注释；
- 编辑器与画笔模式互斥，避免输入焦点冲突。

## 7. 推荐路线

1. **E1**：只读源码视图升级为可编辑文本视图，支持保存和未保存提示；
2. 加入文件监听与冲突检测；
3. 加入预览同步；
4. 评估 E3 的块级编辑；
5. 完整 WYSIWYG 暂不纳入计划。

## 8. 结论

- 源码编辑：可做，工作量中等；
- 实时预览/冲突处理：可做，工作量中高；
- 预览内直接编辑：难度高，需先有稳定的源码映射；
- 完整 WYSIWYG：不符合当前轻量化定位，暂不做。

2.4.0.0 先聚焦路径预览、工作区、ZIP、TOC/标签/监听等阅读体验；编辑能力留作后续独立版本。
