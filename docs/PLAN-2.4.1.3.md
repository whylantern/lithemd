# LitheMD 2.4.1.3 规划：打开文件 / 文件夹与工作区分层预加载

> 状态：2026-11-21 已实施 W1–W10，W11 发布流程进行中。
> 全局约束见 `docs/REQUIREMENTS.md`，架构见 `docs/ARCHITECTURE.md`。

## 1. 版本目标

2.4.1.3 聚焦两件事：

1. 修复打开文件 / 打开文件夹后的工作区行为。
2. 将工作区目录树改为**后台、分层、有预算的预加载**：
   - 根目录向下 3 层优先加载；
   - 每次展开文件夹再加载该文件夹向下 3 层；
   - 当前打开的目录不再使用 4000 项静默截断；
   - 空闲时可在预算内继续加载，但不允许无限占用内存。

不把“完整索引整个磁盘”作为默认行为。

## 2. 当前基线

### 已有交互

2.4.1.2 已经完成：

- 工具栏和欢迎页统一为 `打开 ▾`：
  - 打开文件
  - 打开文件夹
- 右上角 `文件 ▾`：
  - 打开文件夹
  - 显示 / 隐藏工作区
  - 刷新工作区
- 欢迎页最近文件下增加最近工作区。
- `.exe` 等二进制文件在读取前拦截。

### 当前工作区模型

```text
WorkspaceModel
  SetRoot()      枚举根目录直接子项
  Toggle()       展开时加载该文件夹直接子项
  Rows()         只返回已展开节点
  Reveal()       自动沿文件路径逐级展开
  Refresh()      重新加载根目录并恢复展开
```

当前限制：

- `LoadChildren` 在 4000 项处静默停止；
- `Reveal` 会自动加载路径上的多层目录；
- `Refresh` 可能恢复并重载大量深层目录；
- 所有目录枚举在 UI 线程同步执行；
- `Rows()` 每次都复制展开节点的名称和路径。

## 3. 目标加载语义

层级定义：

```text
L0  工作区根目录
L1  根目录的直接子项
L2  L1 文件夹的直接子项
L3  L2 文件夹的直接子项
```

### 3.1 打开工作区

1. UI 线程只同步加载 `L0` 的直接子项，保证窗口立即显示。
2. 后台任务从根目录开始预加载到 `L3`：
   - 每个目录完整枚举，不再 4000 截断；
   - 只处理目录条目，不读取文件内容；
   - 不递归进入 `L3` 文件夹的内部。
3. 预加载完成后，在状态区显示“工作区已加载到第 3 层”。

### 3.2 展开文件夹

用户点击文件夹 `F`：

1. 立即展开 `F` 的已缓存直接子项。
2. 如果直接子项尚未缓存：
   - 显示一个“正在加载…”占位行；
   - 后台枚举 `F` 的直接子项；
   - 完成后替换占位行。
3. 同时排队预加载 `F` 向下 3 层未加载目录：
   - `F` 的直接子项
   - 子文件夹的直接子项
   - 孙文件夹的直接子项
   - 不再自动进入玄孙文件夹。

### 3.3 空闲加载

当用户 2 秒没有鼠标/键盘操作，并且没有正在等待的用户任务时：

1. 后台从已加载边界继续向下扩展 1 层；
2. 每批最多处理固定数量的目录；
3. 每批之间检查预算和取消状态；
4. 达到预算后暂停，不继续吃内存；
5. 用户重新展开文件夹时，用户任务优先。

### 3.4 不截断当前目录

- 移除 4000 项硬截断。
- 当前打开的目录完整枚举。
- 如果单个目录极大，仍完整加载，但显示进度/警告。
- 不使用“静默截断”。

## 4. 内存与预算

“完全不截断 + 完整加载”不能同时保证无限目录安全，因此后台预加载必须有预算。

建议默认值：

| 项目 | 默认值 | 说明 |
|---|---:|---|
| 缓存目录条目 | 200,000 | 约 60–120 MB，取决于路径长度 |
| 缓存字符串内存 | 128 MB | 超过后暂停后台预加载 |
| 单个目录条目 | 不设 4000 截断 | 当前目录完整显示 |
| 后台每批目录数 | 32 | 避免长时间占用磁盘 |
| UI 通知间隔 | 150 ms | 合并刷新 |
| 空闲触发 | 2 秒 | 无鼠标/键盘操作 |

预算只限制“后台继续向深层预加载”，不限制用户主动打开的当前目录。

### 大目录保护

- 单目录超过 20 万项时，当前目录仍完整枚举，但显示：
  - 已加载条目数
  - 内存占用
  - 可取消按钮
- 若单目录达到系统/内存上限：
  - 明确提示“目录过大，已停止继续加载”
  - 不把错误伪装成空目录
  - 提供“在资源管理器中打开”入口

## 5. 数据结构

### 5.1 WorkspaceNode

```cpp
struct WorkspaceNode {
    std::wstring name;
    std::wstring path;
    bool isDir;
    bool loaded;       // 直接子项是否已加载
    bool expanded;
    bool loading;      // 后台正在加载
    bool error;
    uint64_t loadTime; // 最后枚举时间
    int scanDepth;     // 已保证预加载到的相对层数
    std::vector<std::unique_ptr<Node>> children;
};
```

### 5.2 DirectoryCache

新增 Core 层缓存，避免后台线程直接修改 UI 树：

```cpp
struct CachedEntry {
    std::wstring name;
    bool isDir;
};

struct CachedDirectory {
    std::vector<CachedEntry> entries;
    uint64_t timestamp;
    bool complete;
};

class DirectoryCache {
    std::mutex mutex_;
    std::map<std::wstring, CachedDirectory> dirs_;
    // LRU / 预算计数
};
```

后台只写缓存；UI 展开目录时从缓存构建 `WorkspaceNode`。这样：

- 不需要锁住整棵树；
- 枚举慢时不会卡住 UI；
- 缓存可被淘汰，树节点保持稳定。

### 5.3 Scanner

```cpp
class WorkspaceScanner {
public:
    void Start(root, generation, depth);
    void Request(path, depth); // 用户展开优先
    void Stop();
private:
    std::thread worker_;
    std::atomic<bool> stop_;
    std::atomic<uint64_t> generation_;
    std::deque<Job> queue_;
    DirectoryCache cache_;
};
```

任务优先级：

1. 用户刚刚展开的目录；
2. 根目录向下 3 层；
3. 空闲深层扩展。

切换工作区、关闭窗口时：

- 增加 generation；
- 取消旧任务；
- 等待工作线程结束；
- 清空旧缓存。

## 6. UI 行为

### 6.1 工作区树

- 展开文件夹时如果缓存未命中：
  - 显示轻量“正在加载…”行；
  - 不冻结窗口；
  - 完成后替换为真实内容。
- 每个文件夹行可显示加载状态。
- 状态栏显示：
  - “工作区：后台加载 1,240 个目录”
  - “已暂停（内存预算）”
  - “加载完成”
- 不在主界面堆叠技术性说明。

### 6.2 打开 / 定位

- `OpenFile` / `OpenWorkspace` 仍走现有统一入口。
- `Reveal` 默认只高亮已加载节点：
  - 不因为打开文件而自动展开多层；
  - 用户主动点击“在文件树中定位”时才沿路径加载。
- 切换标签不再触发深层自动加载。

### 6.3 刷新

`Refresh` 改为：

1. 重新枚举根目录直接子项；
2. 只恢复根目录下一层的展开状态；
3. 更深层保留在缓存中，用户展开时再构建；
4. 不递归重新加载所有展开目录。

## 7. 打开文件 / 文件夹逻辑修复

除预加载外，2.4.1.3 一并修复：

### 7.1 `loading_` 请求丢失

`OpenFile` 目前遇到 `loading_` 直接返回。改为：

- 维护一个待处理打开队列；
- 当前打开完成后依次处理；
- 或明确显示“正在打开，请稍候”。

### 7.2 切换标签取消保存

已在 2.4.1.2 修复：

- 用户取消保存时，不再错误重载当前标签。

2.4.1.3 做回归测试，确保不复发。

### 7.3 打开工作区失败

`OpenWorkspace` 失败时：

- 不破坏旧工作区；
- 先构建新模型，成功后再替换；
- 错误提示包含路径；
- 设置窗口不写入无效根目录。

### 7.4 二进制特判回归

保留 2.4.1.2 的名单：

```text
.exe .dll .sys .drv .scr .com .msi .msp .cpl .ocx .efi
.bin .lnk .class .pyc .o .obj .lib
```

所有打开入口必须继续覆盖。

## 9. 验收测试

### 目录

- 3 层测试树：每层 50 个文件夹 / 文件。
- 5,000 项目录：完整显示，不变慢到无法操作。
- 50,000 项目录：显示加载状态，可取消。
- 权限拒绝目录：只标记该节点，不影响父级。
- 符号链接 / junction：不递归。
- 网络目录：默认不进行空闲深层扫描。

### 交互

- 打开工作区：根目录立即出现，3 层后台补充。
- 展开文件夹：直接子项可见；后台继续 3 层。
- 连续展开多个文件夹：请求按优先级处理。
- 切换工作区：旧扫描取消，新工作区不串数据。
- 关闭窗口：扫描线程退出。
- 打开最近文件：不自动展开深层目录。
- 手动“定位”：按需逐层加载。
- 刷新：根目录和一级展开恢复，不递归重载。
- `.exe` 等：读取前拒绝。

### 资源

- 后台扫描期间 UI 仍可滚动、切换标签、关闭窗口。
- 达到缓存预算后暂停，不出现内存持续增长。
- 扫描取消后 3 秒内退出。
- 关闭主窗口后无后台线程残留。
