# 2.6.0.0 编辑功能规划（暂缓）

> 2.5.0.0 不启用、不编译本文件描述的编辑内核；本文件仅作为 2.6.0.0 设计和实现参考。

# LitheMD 全局要求与架构约束

> 每次任务开始前先阅读本文件；实现、测试和提交说明中必须引用对应任务编号。
> 本文件适用于当前及后续版本的全局约束，优先级高于局部实现便利。

## 1. 产品定位

- Windows 原生本地文档阅读器，后续加入文件夹工作区、路径预览和 ZIP 浏览/解压。
- 单文件 `lithemd.exe`，离线运行，不依赖 .NET、Java、Node、WebView2 或在线服务。
- 默认保持蓝白简洁风格；功能增加不能变成重型 IDE。
- 所有代码最终静态链接进同一个 exe，不新增运行时 DLL。

## 2. 强制核心要求

### 2.1 分层

```text
UI 层      窗口、Canvas、DirectWrite、鼠标键盘、树、对话框
Core 层    DocumentLoader、ArchiveReader、WorkspaceModel、PathResolver、
           RecentStore、Settings 数据、Export 数据
Platform   文件系统、BCrypt、WIC、Direct2D、Win32 封装
```

- Core 层不得包含 `HWND`、不得直接绘制、不得调用 `InvalidateRect`。
- UI 层不得重复解析 ZIP、密码、路径或文件格式。
- 新增功能优先进入 Core，再由 UI 调用。
- 现有 `app.cpp` / `view.cpp` / `common.cpp` 不要求一次性重写；但新增逻辑不得继续堆入这些文件。
- 2.5.0.0 起，新增的编辑、编码、预览解析逻辑必须放入 `src/core/`；Win32 编辑控件、窗口和滚动条封装放入 `src/platform/win32/`。`app.cpp`、`view.cpp` 只负责命令转发、布局和生命周期。
- 可移植核心按依赖规则判定，不按目录名字判定：Core 文件不得直接或间接包含 `windows.h`、`d2d1.h`、`dwrite.h`、`shlobj.h`、`shellapi.h`、`ole32.h`，不得出现 `HWND`、`HDC`、`ID2D1*`、`CreateFileW`、`Reg*`。
- `common.h` 是历史汇总头，不得继续扩大；新增 Core 头文件不得包含 `common.h`。

### 2.2 单 exe 与依赖

- 不引入 WebView、Electron、Tauri、Node、Rust、Python 运行时。
- 不新增第三方 ZIP 库；使用现有 miniz + Windows BCrypt。
- 新功能不能要求安装额外程序或服务。

### 2.3 安全

- 可执行/系统二进制文件必须在读取和解码前拒绝：
  `.exe .dll .sys .drv .scr .com .msi .msp .cpl .ocx .efi .bin .lnk .class .pyc .o .obj .lib`。
  该规则适用于命令行、拖放、路径输入、最近记录和 ZIP 条目预览。
- ZIP 解压必须防 Zip Slip、绝对路径、盘符、UNC、符号链接和 `..`。
- 必须限制单文件大小、总解压大小、压缩比和页数/条目数。
- 密码只存在内存中，不写入 `config.json`、笔记、日志或最近记录。
- 错误不得泄露本机敏感路径以外的内容；UI 只显示必要的路径和错误。
- 不允许静默覆盖用户文件。

### 2.4 性能

- 目录枚举必须分层：根目录先显示，后台按 3 层预加载；展开文件夹再加载向下 3 层。
- 目录扫描不得在 UI 线程递归；后台缓存超过预算时暂停深层预加载，不静默截断当前目录。
- ZIP、PDF、Office、密码校验等阻塞操作不得卡住 UI 线程。
- 大文件、压缩炸弹、超长路径必须有明确上限和取消路径。
- 打开普通文档的启动时间不得因工作区树或 ZIP 支持明显变慢。

### 2.5 错误与文案

- 新 Core 代码优先返回错误码/结构化结果，由 UI 翻译为当前语言。
- 用户可见文案必须必要、简洁，不解释实现细节。
- 新增文案必须同时提供中文、英文，并兼容外部翻译文件。

### 2.6 测试

- 每个任务必须有可复现的验收步骤。
- 涉及文件系统的测试必须使用临时目录，不修改真实用户最近记录和笔记。
- 构建和测试尽量静默运行，不抢占前台焦点。

### 2.7 Git

- 按用户要求：仅在版本更新时提交 GitHub。
- 平时本地实现、构建、测试，不推送中间修复。
- 版本更新时提交源码、文档和 `dist/lithemd.exe`。

### 2.8 逻辑分层、复用与重绘生命周期（强制）

本节用于避免再次出现“快速缩放/调整透明度时短暂黑屏”一类问题。

#### 2.8.1 渲染资源必须复用

- 窗口级 `Canvas` / Direct2D render target 必须作为窗口对象的成员长期复用。
- 禁止在每次 `WM_PAINT` 中创建并销毁 `Canvas` 或 `ID2D1HwndRenderTarget`。
- `Canvas::Begin` 只负责调整尺寸、清屏、更新调色板和开始绘制；不得隐式重建整条渲染链。
- 尺寸或 DPI 变化必须由 `Canvas` 统一处理；resize 失败必须丢弃并重建，不能继续使用旧尺寸。
- 所有自绘窗口（主窗口 chrome、设置、快捷键等）遵循同一规则。

#### 2.8.2 状态变化只失效相关资源

- 透明度、裁剪位置、填充方式等纯绘制参数变化，不得清空图片缓存或重新解码背景。
- 只有图片路径变化时才允许清空该图片的资源缓存。
- 设置变更不得无条件重建所有标签页、所有列表和所有布局。
- 高频操作（透明度连点、滚轮、缩放、窗口拖动）不得在每一次步进中同步写磁盘；确需持久化时应合并或延迟保存。
- 共享布局计算（主页指标、列表行高、滚动范围）必须只有一个来源，绘制、命中测试和滚动条不能各自复制一份算法。

#### 2.8.3 重绘调度

- `WM_SIZE` 中只移动当前活动视图；隐藏标签在激活时再布局。
- 禁止对全部标签页使用 `MoveWindow(..., TRUE)` 强制同步重绘。
- 窗口尺寸变化时同步重绘父窗口 chrome，并用短定时器做一次收尾全量重绘。
- `WM_EXITSIZEMOVE` 必须做一次最终完整重绘。
- 绘制入口必须保证清屏或完整覆盖；不能依赖 D2D 表面在 resize 后保留旧内容。
- 父窗口和子窗口的无效区域必须分别处理；不能只失效子视图而留下黑色 chrome。

#### 2.8.4 分层职责

- 渲染目标生命周期属于 UI 层，由窗口对象管理。
- 图片存储、配置持久化、路径解析属于 Core 层；UI 不直接拼路径或写配置文件。
- 设置窗口只发出设置变更，不直接操作主窗口的 HWND、标签页或 Canvas。
- 主窗口负责把变更广播给 view；view 只更新自己的状态并失效自身。
- 新增重复布局、重复滚动或重复渲染目标逻辑，视为架构回归。

#### 2.8.5 必测回归场景

每个涉及设置或窗口尺寸的版本至少验证：

1. 连续快速拖动窗口边缘 30 次，标题栏、标签栏、状态栏、内容区不出现持续黑块。
2. 连续快速点击背景透明度 `+`/`-` 20 次，设置窗口和主窗口不黑屏。
3. 调整透明度、填充方式、裁剪位置后背景不重新解码，画面连续。
4. 最小窗口、宽而矮窗口、最大化窗口下主页列表可滚动且不重叠。
5. 设置窗口输入非法透明度时不修改原值，并给出提示。

## 3. 2.6.0.0 编辑功能规划（暂缓）

> 版本号：`2.6.0.0`。
> 发布策略：本地构建并截图确认后，才允许更新 GitHub；用户未确认前不推送、不改 tag、不替换 Release 资产。
> 任务按依赖顺序编号；标“可并行”的任务不阻塞主链路。

### 3.1 范围与产品决策

**可编辑格式**

- Markdown：`.md .markdown .mdown .mkd .mdx`。
- 纯文本/源码：`DocKind::Text`，包括 `.txt .log .yml .yaml` 及代码文件。
- 其他格式保持现状，只读预览：JSON、Notebook、Chat、CSV、DOCX/DOC、XLSX/XLS、PDF、图片。

**编辑形态**

- 2.6.0.0 采用“源码编辑 + 实时预览”，对应 MarkText 的 source/split 模式：
  - Markdown：左侧原生多行编辑器，右侧实时预览；分隔条可拖动；预览可隐藏。
  - 纯文本/源码：整窗编辑器，不显示 Markdown 预览。
- 本版本不实现块级 WYSIWYG。原因：Win32 下自建富文本排版、IME、选区、撤销和光标命中风险不可控；先交付稳定的源码编辑与预览，并为后续 WYSIWYG 保留 `EditSession` 和宿主边界。
- 2.6.0.0 明确不实现类 Typora 的编辑器内核。该方向作为 2.6+ 的独立项目，内核按“纯 C++ + 平台接口”设计，三平台共用；2.6.0.0 不为其提前写 Win32 专用富文本代码。
- 编辑器首版使用原生 `EDIT` 控件：保留系统 IME、撤销、剪贴板、拖选和无障碍能力；不自绘文本框。

**非目标**

- 不做多光标、块级拖放、实时协作、Vim/Emacs 键位。
- 不做 Markdown 格式化工具栏（加粗/链接等）的首版入口；后续版本再加。
- 不做自动保存；只做显式保存。
- 不改变阅读模式的画笔、笔记、分屏和导出行为。

### 3.2 编辑功能逻辑

**进入/退出**

- 只有 `CanEdit()` 为真的文档显示“编辑”按钮：Markdown 或 Text，路径存在，文件可写，大小不超过 8 MiB。
- 进入编辑：读取 `Document::text`，填充编辑器，记录原始编码、BOM、换行风格；Markdown 创建预览视图。
- 退出编辑：无修改直接退出；有修改时弹出“保存 / 不保存 / 取消”。
- `Ctrl+E` 切换编辑，`Ctrl+S` 保存；编辑器聚焦时只放行这两个应用命令，复制、粘贴、撤销、全选等交给原生 `EDIT`。

**实时预览**

- Markdown 文本变化后 180–250 ms 防抖刷新预览。
- 预览复用现有 `Document` 渲染器；预览视图不加载笔记、不进入编辑、不参与大纲。
- 预览刷新保持滚动比例，避免每次输入跳回顶部。
- 文本超过 2 MiB 时暂停自动预览，保存或手动刷新时再生成；超过 8 MiB 禁止进入编辑。

**保存**

- 保存到原文件，不做“另存为”。
- 保留原编码：UTF-8、UTF-8 BOM、UTF-16 LE/BE、UTF-32 LE/BE、GB18030/GBK/Big5/Shift-JIS/Windows-125x/Latin-1。
- 保留原换行风格：CRLF、LF、CR；编辑器内部使用 CRLF，写盘前转换。
- 原子写入：同目录临时文件 + `ReplaceFileW`/`MoveFileExW`；失败时保留脏状态并提示，不截断原文件。
- 保存成功后更新 `Document`、标签页 `fileTime`、窗口标题和状态栏；清空脏标记。

**脏状态与外部修改**

- 首次用户输入即标记脏；保存后清除。标题追加 `*`，状态栏显示“未保存”。
- 关闭标签、关闭窗口、刷新、切换外部修改标签前，必须处理未保存编辑。
- 编辑中检测到外部修改：不静默重载；在状态栏提示，用户保存时提示覆盖风险，退出时按未保存流程处理。
- 笔记未保存与文档未保存合并为一次确认，避免连续弹窗。

**布局与主题**

- 编辑窗格与预览窗格默认 50/50；拖动分隔条调整，双击恢复 50/50。
- 深色模式：编辑器背景、文字、滚动条、预览背景、分隔条全部使用当前主题；原生标题栏继续使用 DWM 深色。
- 状态栏右侧显示“编辑中”或“编辑中 · 实时预览”；左侧保留编码、行数和未保存提示。

### 3.3 代码边界

**新增 Core（`src/core/`，不得包含 Win32）**

- `edit_session.h/.cpp`：编辑状态、路径、编码、BOM、换行、脏标记、大小限制。
- `text_codec.h/.cpp`：`DetectLineEnding`、UTF 编码、传统代码页编码回调、保存字节生成。
- `markdown_preview.h/.cpp`：从 Markdown 文本构建只读 `Document`，不访问文件系统。2.5.0.0 先以 `document.cpp` 中的 `BuildMarkdownPreviewDocument` 入口交付，2512 再迁移到 core。
- 后续拆分：`base.h`（纯类型/枚举/颜色/字符串工具）、`document_parse`（文本→Document）、`math_parse`（LaTeX 解析与绘制分离）。

**新增 Platform/UI（`src/platform/win32/`）**

- `editor_pane.h/.cpp`：Win32 子窗口，拥有 `EDIT`、预览 `DocView`、分隔条、防抖定时器、主题和焦点。
- 通过回调向 `DocView` 报告：文本变化、保存请求、退出请求、脏状态变化、光标行号。
- `view.cpp` 只做委托和布局，不直接操作 `EDIT` 的内部状态。
- `app.cpp` 只做命令、工具栏、快捷键、确认框和文件时间同步。

**2.6.0.0 必须完成的边界**

- 新增编辑代码不得直接写入 `app.cpp` / `view.cpp` / `common.cpp`。
- `view.cpp` 只增加 `EditorPane` 成员和转发接口。
- `common.h` 不增加新 API；编辑相关类型放 `src/core/`。
- 现有 `app.cpp` / `view.cpp` / `common.cpp` 的大拆分不在本版本强行完成；`base.h`、`document_parse`、`math_parse` 作为后续独立任务，避免阻塞编辑交付。

### 3.5 验收场景

1. 打开 Markdown，点击“编辑”，左右分栏出现；输入后 300 ms 内预览更新。
2. 拖动分隔条到 30/70，预览隐藏后编辑器占满；退出编辑后阅读视图滚动位置合理。
3. `Ctrl+S` 保存，标题 `*` 消失；关闭再打开，内容和编码一致。
4. 打开 UTF-8 BOM、UTF-16 LE、GBK 各一个文件，编辑保存后字节级检查 BOM 和编码。
5. 打开 CRLF 与 LF 的 Markdown，保存后换行风格不变。
6. 打开 TXT，编辑器整窗显示，无预览；打开 JSON/CSV/PDF/Office，无“编辑”按钮。
7. 修改后关闭标签：取消保留；不保存丢弃；保存写盘。
8. 编辑中从外部修改文件：状态栏提示，内容不被静默覆盖。
9. 深色模式下编辑器、滚动条、预览、调色盘、导出窗口标题栏均为深色。
10. 连续缩放、拖动窗口、切换标签，编辑器和预览不黑屏、不丢焦点。
11. 调色盘：新建立即出现，删除按钮生效，主栏可取消并补满，`备选 n/12 · 主栏 n/5` 正确。
12. 8 MiB 以上文件不显示编辑入口；2 MiB 以上 Markdown 暂停自动预览但可保存。

## 4. 任务执行规则

1. 开始任务前阅读本文件，确认任务编号和验收。
2. 先改 Core/数据模型，再接 UI；不要在 `app.cpp` 临时堆逻辑。
3. 独立功能优先拆成新文件；修改共享文件前先检查是否已有可复用接口。
4. 每完成一个任务：编译、运行对应验收、更新本表状态。
5. 不在任务之间顺手重构无关代码；避免扩大回归面。
6. 版本更新时才提交 GitHub。
7. **版本发布后清空第 3 节**，不在文件中保留当前版本号或已完成任务清单。
8. 新要求先写入第 3 节，再按顺序拆解；可并行的任务明确标注，合并、构建和发布仍串行。
