# 背景图片：导入、裁剪与缩放

> 基线：2.4.2.0。本文记录背景图片的最终产品决策和实现规则。

## 1. 结论

不要求用户先自行裁剪图片，也不做会修改原图的“导入裁剪”窗口。

推荐流程：

```text
选择完整图片
  -> 立即应用为背景
  -> 选择填充方式
  -> 选择裁剪位置
  -> 通过透明度控制阅读干扰
```

理由：

- 原图不被修改，用户之后仍可换窗口尺寸或换填充方式。
- 不需要实现复杂的裁剪框、拖拽句柄、比例锁定和取消/重做。
- 窗口大小、DPI、分屏和最大化都会变化，固定裁剪区域反而不如实时布局。
- 需要精确构图的用户仍可以在外部先裁剪，再导入；程序不会强制这一步。

## 2. 填充方式

| 方式 | 行为 | 适用 |
|---|---|---|
| 铺满裁剪（默认） | 等比放大到覆盖窗口，超出部分裁掉 | 大多数照片和插画 |
| 完整显示 | 等比缩小到完整放入窗口，四周用主题背景补齐 | 不想丢失任何画面 |
| 拉伸 | 强制铺满窗口 | 纯色、渐变、抽象图 |
| 平铺 | 按图片原始尺寸重复，过小的图会放大到至少 128 DIP | 纹理、图案、小图标 |

所有模式在窗口大小变化时实时重新计算，不会保存固定像素尺寸。

## 3. 裁剪位置

“铺满裁剪”会出现横向或纵向溢出。提供 3×3 位置：

```text
左上   上   右上
左     中   右
左下   下   右下
```

默认“中”。它只决定溢出部分保留哪一边，不改变图片比例：

```text
scale = max(viewW / imageW, viewH / imageH)
offsetX = (viewW - imageW * scale) * anchorX
offsetY = (viewH - imageH * scale) * anchorY
```

- `anchorX` / `anchorY` 取 0、0.5、1。
- 位置只对“铺满裁剪”生效；“完整显示”“拉伸”“平铺”忽略它。
- 这样既能让用户选择保留人物头部、建筑顶部等区域，又不需要任意裁剪框。

## 4. 透明度

- 范围：5%–60%。
- 默认：15%。
- 步进：5%。
- 设置保存到 `config.json` 的 `backgroundOpacity`。

默认 15% 是为了保证正文、最近记录和工作区历史的可读性。用户可以在设置中调高，但不会允许完全遮住文字。

## 5. 图片格式与安全限制

通过 Windows WIC 解码，支持系统已安装编解码器的常见格式：

- PNG
- JPEG / JPG / JPE / JFIF
- BMP
- GIF（第一帧）
- TIFF（第一页）
- WEBP（依赖系统 WIC 编解码器）
- ICO（第一帧）

选择图片时先验证：

- 文件不超过 64 MB；
- 像素不超过 6,000 万；
- WIC 能读取第一帧。

验证失败会给出明确提示，不会把无效路径保存为背景。

背景图片只读本地文件，不下载网络图片，不执行图片内容。

## 6. 与页面模式的关系

背景绘制在内容之前：

```text
主题底色
  -> 背景图片
  -> 正文 / 列表 / PDF 页面 / 图片
```

- 主页、Markdown/文本正文、PDF 和图片四周会显示背景。
- 源码、JSON、表格模式保留自己的不透明工作区，避免干扰。
- PDF 页面和图片本身保持原样，不会被背景覆盖。
- 导出 PNG/PDF 默认不包含背景；背景只是阅读界面设置。

## 7. 相关文件

| 文件 | 内容 |
|---|---|
| `src/common.h/.cpp` | `backgroundImage`、`backgroundOpacity`、`backgroundFit`、`backgroundAnchor` 的持久化与范围限制 |
| `src/view.h/.cpp` | `PaintBackground`、四种填充方式、3×3 裁剪位置 |
| `src/app.cpp` | 设置页背景区块、图片选择、格式与大小验证 |
| `src/i18n.cpp` | 背景相关中英文文本 |

## 8. 后续可选增强

如果用户确实需要任意区域裁剪，建议单独做“裁剪副本”功能，而不是改变背景导入流程：

- 在独立窗口中拖拽裁剪框；
- 输出到配置目录下的新图片；
- 保留原图不变；
- 背景设置指向裁剪副本。

该功能成本明显高于当前的“填充方式 + 九宫格位置”，暂不纳入首个背景版本。
