# LitheMD 全局要求与架构约束

> 每次任务开始前先阅读本文件；实现、测试和提交说明中必须引用对应任务编号。
> 本文件适用于当前及后续版本的全局约束，优先级高于局部实现便利。

## 1. 产品定位

- Windows 原生本地文档阅读器，后续加入文件夹工作区、路径预览和 ZIP 浏览/解压。
- 单文件 `lithemd.exe`，离线运行，不依赖 .NET、Java、Node、WebView2 或在线服务。
- 默认保持蓝白简洁风格；功能增加不能变成重型 IDE。
- 所有代码最终静态链接进同一个 exe，不新增运行时 DLL。

## 2. 强制核心要求

### 2.1 分层

```text
UI 层      窗口、Canvas、DirectWrite、鼠标键盘、树、对话框
Core 层    DocumentLoader、ArchiveReader、WorkspaceModel、PathResolver、
           RecentStore、Settings 数据、Export 数据
Platform   文件系统、BCrypt、WIC、Direct2D、Win32 封装
```

- Core 层不得包含 `HWND`、不得直接绘制、不得调用 `InvalidateRect`。
- UI 层不得重复解析 ZIP、密码、路径或文件格式。
- 新增功能优先进入 Core，再由 UI 调用。
- 现有 `app.cpp` / `view.cpp` / `common.cpp` 不要求一次性重写；但新增逻辑不得继续堆入这些文件。
- 2.5.0.0 起，新增的编辑、编码、预览解析逻辑必须放入 `src/core/`；Win32 编辑控件、窗口和滚动条封装放入 `src/platform/win32/`。`app.cpp`、`view.cpp` 只负责命令转发、布局和生命周期。
- 可移植核心按依赖规则判定，不按目录名字判定：Core 文件不得直接或间接包含 `windows.h`、`d2d1.h`、`dwrite.h`、`shlobj.h`、`shellapi.h`、`ole32.h`，不得出现 `HWND`、`HDC`、`ID2D1*`、`CreateFileW`、`Reg*`。
- `common.h` 是历史汇总头，不得继续扩大；新增 Core 头文件不得包含 `common.h`。

### 2.2 单 exe 与依赖

- 不引入 WebView、Electron、Tauri、Node、Rust、Python 运行时。
- 不新增第三方 ZIP 库；使用现有 miniz + Windows BCrypt。
- 新功能不能要求安装额外程序或服务。

### 2.3 安全

- 可执行/系统二进制文件必须在读取和解码前拒绝：
  `.exe .dll .sys .drv .scr .com .msi .msp .cpl .ocx .efi .bin .lnk .class .pyc .o .obj .lib`。
  该规则适用于命令行、拖放、路径输入、最近记录和 ZIP 条目预览。
- ZIP 解压必须防 Zip Slip、绝对路径、盘符、UNC、符号链接和 `..`。
- 必须限制单文件大小、总解压大小、压缩比和页数/条目数。
- 密码只存在内存中，不写入 `config.json`、笔记、日志或最近记录。
- 错误不得泄露本机敏感路径以外的内容；UI 只显示必要的路径和错误。
- 不允许静默覆盖用户文件。

### 2.4 性能

- 目录枚举必须分层：根目录先显示，后台按 3 层预加载；展开文件夹再加载向下 3 层。
- 目录扫描不得在 UI 线程递归；后台缓存超过预算时暂停深层预加载，不静默截断当前目录。
- ZIP、PDF、Office、密码校验等阻塞操作不得卡住 UI 线程。
- 大文件、压缩炸弹、超长路径必须有明确上限和取消路径。
- 打开普通文档的启动时间不得因工作区树或 ZIP 支持明显变慢。

### 2.5 错误与文案

- 新 Core 代码优先返回错误码/结构化结果，由 UI 翻译为当前语言。
- 用户可见文案必须必要、简洁，不解释实现细节。
- 新增文案必须同时提供中文、英文，并兼容外部翻译文件。

### 2.6 测试

- 每个任务必须有可复现的验收步骤。
- 涉及文件系统的测试必须使用临时目录，不修改真实用户最近记录和笔记。
- 构建和测试尽量静默运行，不抢占前台焦点。

### 2.7 Git

- 仅在用户确认版本内容没有问题后才提交 GitHub；未确认前不推送、不建 tag、不上传 Release 资产。
- 平时本地实现、构建、测试，不推送中间修复。
- 用户确认后才提交源码、文档和 `dist/lithemd.exe`。

### 2.8 逻辑分层、复用与重绘生命周期（强制）

本节用于避免再次出现“快速缩放/调整透明度时短暂黑屏”一类问题。

#### 2.8.1 渲染资源必须复用

- 窗口级 `Canvas` / Direct2D render target 必须作为窗口对象的成员长期复用。
- 禁止在每次 `WM_PAINT` 中创建并销毁 `Canvas` 或 `ID2D1HwndRenderTarget`。
- `Canvas::Begin` 只负责调整尺寸、清屏、更新调色板和开始绘制；不得隐式重建整条渲染链。
- 尺寸或 DPI 变化必须由 `Canvas` 统一处理；resize 失败必须丢弃并重建，不能继续使用旧尺寸。
- 所有自绘窗口（主窗口 chrome、设置、快捷键等）遵循同一规则。

#### 2.8.2 状态变化只失效相关资源

- 透明度、裁剪位置、填充方式等纯绘制参数变化，不得清空图片缓存或重新解码背景。
- 只有图片路径变化时才允许清空该图片的资源缓存。
- 设置变更不得无条件重建所有标签页、所有列表和所有布局。
- 高频操作（透明度连点、滚轮、缩放、窗口拖动）不得在每一次步进中同步写磁盘；确需持久化时应合并或延迟保存。
- 共享布局计算（主页指标、列表行高、滚动范围）必须只有一个来源，绘制、命中测试和滚动条不能各自复制一份算法。

#### 2.8.3 重绘调度

- `WM_SIZE` 中只移动当前活动视图；隐藏标签在激活时再布局。
- 禁止对全部标签页使用 `MoveWindow(..., TRUE)` 强制同步重绘。
- 窗口尺寸变化时同步重绘父窗口 chrome，并用短定时器做一次收尾全量重绘。
- `WM_EXITSIZEMOVE` 必须做一次最终完整重绘。
- 绘制入口必须保证清屏或完整覆盖；不能依赖 D2D 表面在 resize 后保留旧内容。
- 父窗口和子窗口的无效区域必须分别处理；不能只失效子视图而留下黑色 chrome。

#### 2.8.4 分层职责

- 渲染目标生命周期属于 UI 层，由窗口对象管理。
- 图片存储、配置持久化、路径解析属于 Core 层；UI 不直接拼路径或写配置文件。
- 设置窗口只发出设置变更，不直接操作主窗口的 HWND、标签页或 Canvas。
- 主窗口负责把变更广播给 view；view 只更新自己的状态并失效自身。
- 新增重复布局、重复滚动或重复渲染目标逻辑，视为架构回归。

#### 2.8.5 必测回归场景

每个涉及设置或窗口尺寸的版本至少验证：

1. 连续快速拖动窗口边缘 30 次，标题栏、标签栏、状态栏、内容区不出现持续黑块。
2. 连续快速点击背景透明度 `+`/`-` 20 次，设置窗口和主窗口不黑屏。
3. 调整透明度、填充方式、裁剪位置后背景不重新解码，画面连续。
4. 最小窗口、宽而矮窗口、最大化窗口下主页列表可滚动且不重叠。
5. 设置窗口输入非法透明度时不修改原值，并给出提示。

### 2.9 缺陷修复原则（强制）

- 修复 BUG 前必须先复现并定位根因；不能只根据现象加空指针判断、延时、重试、吞异常或临时隐藏控件。
- 从底层代码和逻辑调度查找原因：调用链、对象生命周期、窗口/渲染目标的所有权、消息顺序、线程切换、文件时间与配置状态。
- 修复应放在错误所属层：Core 数据/解析错误在 Core 修，UI 生命周期和消息顺序在 UI 宿主修，构建/工具链问题在构建配置修。
- 不允许用“补丁式”修复扩大分支、增加特殊状态或复制逻辑；修完后删除临时调试代码和临时绕过路径。
- 每个 BUG 修复必须有可复现的验收步骤，并检查同类窗口/路径是否受同一根因影响。
- 修复说明必须写明根因、修改点和回归范围，不能只写“修复某问题”。

### 2.10 版本验证与测试

- 每完成一个任务就单独验证，不把全部任务堆到最后一次性测试。
- 测试使用临时目录、临时文件、单实例和有限样本；不做高频/整机压力冒烟，避免测试机器崩溃。
- 所有任务完成后做一次调用链、生命周期、消息顺序、渲染目标和配置状态的逻辑检查，再进入发布确认。
- 验证结果写入任务表；未验证项不能标记完成。

## 3. 2.5.1.0 任务清单

> 版本号：`2.5.1.0`。
> 发布策略：本地实现、逐项验证、最终逻辑检查；用户确认版本内容没有问题后才上传 GitHub。
> 2.5.1.0 仍保持 Windows 原生、单 exe、离线运行。

### 3.1 范围

- 画布/选择模式：拖动平移、滚轮缩放选中笔迹。
- 选择命中：整个选择框可拖动，范围略宽。
- 旋转按钮：修复旋转中心和变换逻辑。
- 复制/粘贴笔迹：修复无法粘贴、粘贴重合、粘贴后不在选择模式。
- 画笔自动识别：停笔约 1 秒后把曲线识别为直线、矩形、圆形/椭圆、三角形。
- 鼠标样式：不同画笔工具和选择区域使用不同光标。
- 全屏笔迹：桌面最上层透明批注层 + 桌面工具栏。
- 适配双指滑动/横向滚轮，不误画。
- 不包含 ClassIn 的截图、摄像头、云盘、多人协作、50 页连续黑板和 `.edb` 文件格式；这些留待后续版本。

### 3.2 选择与笔迹交互

**选择框拖动**

- 选中对象后，整个选择矩形（含内框和外围约 10 DIP 的扩展区）都可以按住拖动。
- 命中优先级：旋转柄 > 四角缩放手柄 > 选择框内部平移 > 框外空白开始套索。
- 选择框边框本身也必须可拖动，不能只命中笔迹线条。
- 拖动使用现有 `InkSelectBeginDrag(..., 1)`，不新增第二套平移逻辑。

**滚轮缩放**

- 选择模式且有选中对象时，滚轮上下缩放选中内容；没有选择时滚轮保持滚动页面。
- 每个滚轮格的缩放比例由 `wheelStep_` 决定，例如 `1 + 0.02 * wheelStep_`；滚轮速度设置同时影响缩放速度。
- 以选择框屏幕中心为缩放中心；一次滚轮格对应一次 undo，不产生连续拖动状态。
- 图片批注使用归一化坐标，必须通过屏幕坐标转换，不能直接乘内容坐标。

**旋转**

- 旋转中心统一使用选择框中心的屏幕坐标。
- 工具栏旋转按钮与旋转柄共用 `InkApplySelectionTransform(3, ...)`，不得一处用内容坐标、一处用屏幕坐标。
- 旋转角度归一化到 `(-π, π]`，多次旋转不累积异常大角度。
- 旋转前后选择框、缩放/旋转柄和命中范围同步更新。

**复制/粘贴**

- 复制/粘贴偏移改为屏幕空间约 24 DIP，再转换到内容坐标；图片批注不能被偏移到画布外。
- 每次粘贴偏移递增，连续粘贴不会完全重叠。
- 粘贴成功后自动切换到选择模式，并选中新粘贴的笔迹/图形/文字。
- 保留组关系并重新分配组号；粘贴后立即可拖动、缩放、旋转和删除。
- 空剪贴板或非画笔模式不产生半成品状态。

**自动识别规则图形**

- 画笔停笔约 1000 ms 后检查最后一条笔迹；新笔迹、擦除、清空、撤销、切换工具时取消等待。
- 识别：直线、矩形/正方形、圆/椭圆、三角形（可后续扩展）。
- 判定基于闭合性、包围盒、点到边距离、径向误差和最小尺寸；低置信度保持原笔迹，不强行改形。
- 识别成功用 `InkShape` 替换原 stroke，保留颜色、线宽和组号；不额外产生一份重叠笔迹。
- 识别失败不弹提示、不改变笔迹。

**双指滑动**

- `WM_MOUSEWHEEL` / `WM_MOUSEHWHEEL` 在画笔模式下仍然滚动/平移画布，不能开始画线。
- 支持触摸板双指滑动；不把滚动手势解释为指针按下。
- 如系统发送 `WM_GESTURE`，只处理平移手势，绘制仍由单指针完成。

**鼠标样式**

| 场景 | 光标 |
|---|---|
| 鼠标/退出工具、工具栏空白 | 箭头 / 手形 |
| 画笔、直线、箭头、矩形、椭圆、荧光笔 | 十字 |
| 橡皮 | 自定义橡皮方块或方形光标 |
| 文字 | I 形 |
| 选择工具空闲 | 箭头 |
| 选择框内部平移 | 四向移动 |
| 四角缩放 | 对应斜向缩放 |
| 旋转柄 | 旋转/手形 |
| 拖动画布 | 四向移动 |

- 光标切换由当前工具、指针命中的手柄/选择框/工具栏和拖动状态共同决定，不能只在进入画笔模式时设置一次。

### 3.3 全屏笔迹

**定位**

- 参考 ClassIn 桌面批注：笔迹是桌面最上层叠加层，不修改桌面文件；退出后桌面恢复原状。
- 覆盖虚拟桌面（多显示器按虚拟屏幕边界），不是只覆盖 LitheMD 窗口。
- 鼠标工具下窗口点击穿透，可操作桌面或其他软件；画笔/选择/橡皮工具下捕获指针绘制。

**入口/退出**

- 在主界面“画笔”按钮或画笔工具条上右键，弹出“进入全屏笔迹”；正常左键仍进入现有画笔。
- 全屏工具栏“返回”或 `Esc` 隐藏桌面批注笔迹，笔迹数据保留；再次进入全屏笔迹时恢复显示并可继续编辑。橡皮右键菜单“清屏”清除全部临时笔迹。退出/隐藏/清屏不写入文档笔记。
- 退出后恢复主窗口焦点和原画笔状态。

**桌面工具栏**

- 采用一行紧凑横向浮动工具栏，默认底部居中，避免遮挡屏幕中央内容。
- 顺序：`拖动标签 | 鼠标 | 选择 | 画笔 | 橡皮 | ↶ ↷ | 颜色1 颜色2 颜色3 调色盘 | 返回 | 设置 | 收缩`。
- 工具栏使用主设置窗口同一主题的 surface/border/accent 配色，窗口区域裁剪为圆角。
- 最左侧为按住可拖动的小标签；右侧收缩按钮把工具栏收成屏幕左/右侧的小标签，点击小标签展开。
- 窄屏/小屏时自动分成两行：上排工具，下排颜色、返回、设置。
- 工具栏为独立 topmost 窗口，始终位于批注层之上；批注层鼠标穿透时工具栏不受影响。
- 工具栏与主窗口生命周期解耦：主窗口最小化/隐藏时叠加层和工具栏保持显示，画笔/选择/橡皮操作不激活主窗口。
- 返回/Esc 隐藏桌面笔迹（数据保留），再次进入时恢复显示；橡皮右键菜单提供“清屏”立即清除全部临时笔迹（无需二次确认）。
- 工具按钮显示当前选中状态；颜色按钮显示色块和选中描边。

**颜色模型**

- 调色盘颜色数组 `inkPresets` 全局同步：调色盘新增/删除/修改后，主栏和全屏栏都看到同一组颜色。
- 主栏选择 `inkToolbarPresets`（最多 5 个）和全屏选择 `fullscreenInkPresets`（固定 3 个）相互独立。
- 两个选择都持久化到 `config.json`；删除颜色时同步修正两组索引。
- 全屏调色盘入口打开现有调色盘；选色结果只更新当前全屏槽位，不自动改动主栏槽位。

**全屏选择**

- 选择工具与文档画笔选择保持一致：拖动框选/点击选择、选择框整体平移、四角缩放、顶部旋转柄、滚轮缩放。
- 选择工具条提供复制、粘贴、组合、拆组、旋转 90°、删除；Ctrl+A/C/V/D 与方向键同样可用。
- Backspace/Delete 直接删除选中笔迹；选择操作均进入撤销/重做栈。

**设置**

- 全屏笔迹设置放在主设置窗口的新“全屏笔迹”分区，不单独再建一套配置窗口。
- 工具栏“设置”打开主设置窗口并定位到该分区（或先打开设置窗口，用户可看到分区）。
- 分区内容：工具栏位置（底部/顶部）、3 个颜色槽、画笔大小/橡皮大小、是否启用双指平移。
- 所有设置写入现有 `Settings` 和 `config.json`，不新增独立配置文件。

**实现边界**

- 新增独立 `FullscreenInkOverlay`/`FullscreenInkToolbar`，不把桌面批注逻辑塞入 `app.cpp`/`view.cpp`。
- 叠加层使用分层窗口 + alpha 位图，背景完全透明；不能出现黑底遮住桌面。
- 复用现有 `InkStroke`/`InkShape`/`InkText` 模型和绘制逻辑；若模型仍私有在 `DocView`，先提取到共享头文件。
- 桌面批注笔迹是临时层，默认不写文档笔记；后续版本再评估保存/截图。

### 3.5 验收场景

1. 选中笔迹，在框内空白、框边、四角、旋转柄分别按下拖动，行为符合优先级。
2. 滚轮在 3/6/10 档滚轮速度下缩放选中对象，速度和设置一致；撤销回到上一大小。
3. 旋转按钮连续点击 4 次，对象绕中心旋转且不偏移；图片批注同样正确。
4. 复制后连续粘贴 3 次，偏移递增、自动选中、可立即拖动；不出现重合或粘贴失败。
5. 画直线、矩形、圆各一条，按住静止 1 秒后识别；自由曲线平滑且不误识别为矩形/椭圆；撤销正常。
6. 逐一切换工具，检查画布、工具栏、选择框、手柄、拖动中的光标。
7. 双指滑动/横向滚轮只平移，不产生笔迹。
8. 右键画笔进入全屏笔迹；鼠标工具可点击桌面；画笔可覆盖任意应用；返回/Esc 隐藏笔迹，再次进入恢复；橡皮右键“清屏”可清除。
9. 全屏工具栏三种颜色与主栏不同但都保存；调色盘颜色两边同步。
10. 全屏设置修改后重启仍生效；删除调色盘颜色不产生越界索引。

## 4. 任务执行规则

1. 开始任务前阅读本文件，确认任务编号和验收。
2. 先改 Core/数据模型，再接 UI；不要在 `app.cpp` 临时堆逻辑。
3. 独立功能优先拆成新文件；修改共享文件前先检查是否已有可复用接口。
4. 每完成一个任务：编译、运行对应验收、更新本表状态。
5. 不在任务之间顺手重构无关代码；避免扩大回归面。
6. 用户确认版本内容没有问题后才提交 GitHub。
7. **版本发布后清空第 3 节**，不在文件中保留当前版本号或已完成任务清单。
8. 新要求先写入第 3 节，再按顺序拆解；可并行的任务明确标注，合并、构建和发布仍串行。
