# 注释保存与导出可行性分析

当前版本（2.2.2.0）的画笔注释是**标签页内存在内存中的浮层**：

- 不修改原文件。
- 每个标签页、每种视图（预览/源码/JSON/表格/PDF/图片）分别保存注释。
- CSV/Excel 按工作表分别保存。
- 关闭标签页后注释释放。

下面分析“保存到文件 / 导出图片 / 导出 PDF / 打印”的可行性与推荐顺序。

---

## 1. 保存注释数据（推荐先做）

### 方案：独立 sidecar 文件

为每个被注释的文件保存一个旁注文件，例如：

```
C:\...\document.pdf
C:\...\document.pdf.lithemd-ink.json
```

或统一放在：

```
%LOCALAPPDATA%\lithemd\annotations\<path-hash>.json
```

建议使用后者，避免在用户目录里散落旁注文件；同时在设置中提供“导出旁注文件”选项。

JSON 结构建议：

```json
{
  "version": 1,
  "source": "C:/docs/document.pdf",
  "sourceSize": 123456,
  "sourceModified": 1794752964309,
  "layers": {
    "preview": {
      "strokes": [{ "points": [[120.5, 80.2]], "color": "#E5484D", "width": 3 }],
      "shapes": [{ "kind": "rect", "a": [10, 20], "b": [200, 120], "color": "#3E63DD", "width": 3 }],
      "texts": [{ "at": [50, 60], "text": "重点", "color": "#E5484D", "size": 20 }]
    },
    "pdf": {},
    "grid:0": {}
  }
}
```

### 可行性：高

- 数据量小，JSON 足够。
- 与现有 `InkStroke / InkShape / InkText` 模型一一对应。
- 加载时按 `source` 路径、文件大小和修改时间匹配；不匹配时提示“注释可能不再对齐”。
- 可自动保存（编辑后 1–2 秒防抖，或关闭标签页/退出应用时保存）。

### 注意事项

- Markdown/HTML 等会随窗口宽度重排的文档，窗口尺寸变化后注释可能偏移。建议保存时同时记录 `viewWidth`、`zoom` 和滚动位置；或只对 PDF/图片提供严格锚定。
- 图片注释已使用归一化坐标，最稳定。
- PDF 注释使用当前缩放下的内容坐标，缩放时已按比例调整；窗口宽度变化会改变页面居中位置，仍可能有轻微横向漂移。

---

## 2. 直接写入原文件

### 可行性：低，不建议作为默认可选

- **图片**：可以把注释烧录成新图片，但会丢失原始像素数据，必须另存副本。
- **PDF**：PDFium 支持创建/写入 PDF 注释（ink annotation），但当前只封装了渲染接口；需要新增 PDFium 注释 API 封装，工作量中等，且不同阅读器显示效果可能不同。
- **DOCX/XLSX**：需要修改 OOXML 包并插入绘图 XML（DrawingML / VML），复杂且容易破坏原文档。
- **DOC/XLS**：旧二进制格式，写入风险高，不建议。
- **Markdown/源码/JSON**：注释不属于源文本，写入会污染原文件。

结论：**默认不修改原文件**；如需要“烧录”应另存副本。

---

## 3. 导出为图片（PNG）

### 可行性：高，但需要离屏渲染改造

当前 `Canvas` 直接绑定 HWND RenderTarget，`PrintWindow` 只能截取可见区域。要导出完整文档/页面，需要：

1. 增加离屏 `IWICBitmapRenderTarget` 或 `ID2D1BitmapRenderTarget`。
2. 让 `Canvas` 支持“目标尺寸 + 缩放 + 渲染到内存位图”。
3. 对文档分页：Markdown 长文档按可视高度切片，PDF 按页渲染，图片直接按图片尺寸渲染。
4. 在离屏画布上重新调用现有 `PaintInk` / 文档绘制函数，叠加注释。
5. 用 WIC PNG 编码器保存。

可分阶段：

- **第一阶段**：导出当前可见区域 PNG（简单，直接复用屏幕渲染）。
- **第二阶段**：导出当前页（PDF/图片）或当前视图完整内容（长文档需要分片）。
- **第三阶段**：导出全部页面/完整文档（需要分页布局）。

---

## 4. 导出为 PDF

### 可行性：中等，工作量高于 PNG

可选路线：

1. **通过 Windows “打印为 PDF”**  
   复用打印管线，让系统 PDF 打印机生成文件。实现成本低，但依赖系统打印机，自动化程度一般。

2. **先渲染成图片，再封装为 PDF**  
   把每页/每屏渲染成位图，使用 PDFium 或第三方轻量 PDF 写入库生成 PDF。文字会变成位图，不可搜索，但实现稳定。

3. **写入原生 PDF 注释**  
   对 PDF 文档最理想：用 PDFium 的 `FPDFAnnot_*` API 把笔画/图形/文字作为 PDF annotation 写入副本。需要扩展当前 PDFium 动态加载封装，工作量中等。

推荐顺序：先做“导出图片 → 再由打印管线生成 PDF”，最后再做原生 PDF 注释。

---

## 5. 打印

### 可行性：高

Windows GDI 打印流程成熟：

- `StartDocW` / `StartPage` / `EndPage` / `EndDoc`
- 获取打印机 DPI 和可打印区域
- 把页面/视图渲染为 DIB 或 WIC 位图，用 `StretchDIBits` / `StretchBlt` 输出
- 长文档需要分页；PDF 按 PDF 页打印；图片按纸张比例缩放

建议先实现：

1. 打印当前视图/当前页。
2. 再实现 PDF 全页打印。
3. 最后实现长文档自动分页打印。

---

## 6. 推荐实施顺序

1. **旁注 JSON 保存/加载**（收益最高、风险最低）
2. **复制当前视图为图片 / 导出当前页 PNG**
3. **打印当前页/当前视图**
4. **PDF 全页导出/打印**
5. **PDF 原生 ink annotation 写入**（高级）
6. **图片烧录另存**（可选）
7. **Office 原文件写入**（不建议）

当前版本已经完成的注释模型（笔画、几何图形、文字、分层、撤销、图片归一化坐标）可以直接复用，不需要重写绘制层。
